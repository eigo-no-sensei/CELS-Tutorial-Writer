# Rust GEL session — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `rust_gel_session`  
**Status:** `active_n1_n2b_read_only`

## Role

- Own authenticated GEL HTTP session state and expose a fixed read-only acquisition surface without leaking credentials/cookies or granting tutorial mutation authority.

## Scope

- Perform the established two-POST Learn2 login handshake and verify both api2 and learn2 authenticated sessions.
- Expose fixed GET methods for open classes, class students, student profile, tutorial list, tutorial summary, tutorial print, current New-tutorial source form and historical tutorial edit pages.
- Acquire a New form only through /study/tutorials/add/{student_uid}/0/{ttype_raw}; the fixed zero locator is read-source semantics and grants no create authority.
- Project tutorial-list JSON to canonical tutorial id/timestamp observations without parsing semantic tutorial content.
- Strip student email-like fields recursively before roster/profile JSON leaves the component.
- Keep credentials transient and cookies private to the session client; expose no generic request function or cookie jar.
- Permit no GEL tutorial create, revise or delete transport.

## Authority

- Transport/acquisition authority only; GEL server remains authoritative for live source content and canonical tutorial IDs.
- The only N1 HTTP POST authority is the two-step Learn2 login handshake; all exposed acquisition operations after authentication are GET.
- N1 does not transfer canonical archive write ownership from the Python v4.9 oracle and does not grant submission authority.

## State transitions

- Unauthenticated -> authenticated only after both api2 and learn2 verification succeed.
- Authenticated -> unauthenticated on HTTP 401/403 or a detected Learn2 login redirect/form.
- Each successful GET replaces the corresponding ephemeral runtime source snapshot; it never promotes the snapshot to canonical local archive state.

## Failure semantics

- Reads fail before transport when the session is unauthenticated.
- Authentication/network/source-shape failures fail closed and never synthesize source values.
- Malformed tutorial-list identity rows fail rather than inventing tutorial_id or timestamp.
- Authentication errors must not include passwords, cookie values, serialized login bodies or full response bodies.
