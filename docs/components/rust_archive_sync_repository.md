**Component ID:** `rust_archive_sync_repository`  
**Status:** `active_a2_canonical`

## Role

- A2 production canonical local-archive implementation: RustArchiver acquires source data and delegates all SQLite mutation to the crate-private transactional ArchiveSyncRepository.

## Scope

- Resolve/create the production schema-v2 archive through RustArchiver; fresh creation is staged and atomically published.
- Acquire open classes, rosters, optional student-profile enrichment, tutorial identities, summary/print/edit source evidence before opening the materialization transaction.
- Preserve Python-v4.9 summary-primary/explicit-blank/print-fallback semantics and recover historical teacher identity from validated edit forms.
- Upsert classes, students, memberships, immutable tutorial identities, source states and field evidence.
- Persist collision groups/group-owned identities/states and governed associations.
- Compute D1-compatible semantic source-state fingerprints.
- Run whole materialization in one transaction and invalidate unseen rows only after a full run is marked complete inside that transaction.
- Audit repository semantic invariants and foreign keys before commit.
- On partial auxiliary summary/print/edit acquisition, preserve prior semantic source evidence for still-observed API tutorial keys while retaining authoritative absence handling for disappeared identities.

## Authority

- Sole production canonical writer of normalized_local_archive and archive_reconciliation_metadata after A2.
- RustArchiver is the public production orchestration entry point; ArchiveSyncRepository remains crate-private and cannot be constructed by external Writer/Viewer consumers.
- Python v4.9 is historical/reference only after A2.
- No authority to mutate live GEL tutorials.

## State transitions

- missing canonical DB -> staged fresh schema-v2 DB -> validated -> atomic rename.
- authenticated source acquisition -> complete in-memory snapshot -> running sync row -> transactional materialization -> complete -> scope-aware invalidation/preservation -> invariant audit -> commit.
- Any operation/finalization failure -> rollback materialization and mark outer sync row failed.
- Unique print-only timestamp may become proven_per_tutorial; same-timestamp collision candidates remain group-owned/fail-closed.

## Failure semantics

- Existing non-v2/invalid archive is rejected; no destructive in-place migration or replacement.
- Canonical tutorial_id re-key attempts fail hard.
- Invalid collision association shape/group ownership fails before write or pre-commit audit.
- Failed/rolled-back sync never invalidates prior source presence; completed FullPreserveSourceEvidence runs may invalidate truly disappeared identities while preserving semantic evidence for still-observed tutorial keys.
- Commit/invariant/FK failure is a hard error; no blind best-effort canonical mutation.
- Partial auxiliary evidence is surfaced in ArchiveSyncReport and cannot erase prior semantic evidence for API tutorial keys still observed in the completed run.
