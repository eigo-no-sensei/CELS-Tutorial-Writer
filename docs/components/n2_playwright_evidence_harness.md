## Role

- Zero-write evidence harness for current GEL New/Edit browser behaviour; core N2 evidence is complete and changed-teacher submit serialization remains a deferred non-blocking diagnostic capability.

## Scope

- Install a context-wide mutation firewall before the first browser navigation and block service workers so browser traffic cannot bypass routing.
- Keep AUTHENTICATION active through the complete two-stage GEL login: manual /corelogin/ submission, GET-only Learn2 session verification, and—when required by the observed historical handshake—manual /user/login submission followed by the same GET-only verification. Credentials remain browser-only in both stages.
- Classify network mutations by authority origin: unexpected GEL-origin mutations are aborted and fail closed; third-party mutating telemetry is aborted without body/header inspection and is non-fatal because it cannot write GEL tutorial state.
- For blocked mutations, stderr-only terminal diagnostics may contain only phase, HTTP method, origin and a redacted path; query parameters, request body, headers, cookies and credential values are forbidden.
- Emit only allowlisted static stage markers during live evidence so a fail-closed exception can be localized without printing student/teacher identity, URLs, form values or network payloads.
- During EVIDENCE, permit no mutation to reach the network. For an explicitly armed /study/tutorials/process POST, reduce only tid/type/customdate/datetime structural relationships in memory and always abort the request.
- Inspect current New forms for Standard/Initial/Final, the latest historical edit form, teacher-control topology and field-by-field New prepopulation behaviour.
- Treat latest tutorial as the already-established New prepopulation source; PW1 records copy/reset/derive relationships rather than attempting provenance inference.
- Where a genuine enabled teacher selector exists, an optional later residual probe may select an alternate only in the browser and observe authentic serialization; this is not required for N2 or normal Writer functionality and never authorizes server reassignment.
- Verify zero writes by fresh GETs: New probes leave the tutorial locator digest unchanged and the revision probe leaves the historical semantic-state digest unchanged.
- Persist only privacy-safe aliases, booleans, counts, non-identity semantic field names, relationship/classification labels, student-free digests and sanitized failure categories under a gitignored evidence directory. student_uid and teacher_id semantic keys are excluded from the persisted prepopulation field map.
- Construct the persisted evidence preamble through a single privacy-validated helper; privacy policy metadata uses non-raw-data key names so the strict global guard can reject identity/body/header fields without false positives.

## Authority

- Evidence-acquisition authority only; no production Tutorial Writer runtime authority.
- May forward the canonical GEL login POST only before EVIDENCE. It has zero GEL tutorial mutation authority.
- Third-party network traffic has no GEL state-writing authority. Blocking third-party telemetry is privacy protection, not GEL contract drift.
- PW1 can record client-side teacher selection but changed-tid serialization/server acceptance is deferred non-blocking and cannot enable Writer reassignment.
- Historical evidence remains authority for NEW-1/TEACHER-1/TEACHER-2/TEACHER-3/UPDATE-1; contradictory live evidence is contract drift requiring review.

## State transitions

- BOOT -> AUTHENTICATION only after the mutation firewall is installed.
- AUTHENTICATION stage 1: operator submits /corelogin/ manually; canonical /user/login POST may be forwarded without body/header inspection; GET-only /administration/students verification decides whether Learn2 is authenticated.
- If stage 1 is not authenticated but a canonical login POST was observed: remain AUTHENTICATION -> GET /user/login -> operator submits that GEL form manually -> repeat GET-only session verification.
- AUTHENTICATION -> EVIDENCE only after the GET-only Learn2 verification succeeds; never transition merely because the operator pressed Enter.
- EVIDENCE optional residual teacher probe -> transient allowlist reduction -> ABORT; this path is not an N2 completion dependency.
- EVIDENCE -> VERIFY -> CLOSED only after fresh GETs prove locator/state digests unchanged.
- Any unexpected GEL-origin mutation, failed second-stage authentication, submission encoding drift or state change -> FAILED_CLOSED; third-party mutating telemetry -> ABORT_NONFATAL and remains in the current state.

## Failure semantics

- Unexpected GEL-origin mutation requests are aborted and fail the run without inspecting their bodies or headers.
- Third-party mutating requests are aborted without body/header inspection, counted separately, and do not fail the run or become GEL contract-drift evidence.
- Blocked-mutation diagnostics contain only phase, method, origin and a redacted path and are terminal-only; queries, bodies, headers, cookies and credential values are never printed or persisted.
- A fail-closed runtime exception may be preceded by an allowlisted static stage marker only; the exception message itself remains suppressed.
- Unexpected tutorial submission encoding is aborted and classified as contract drift; raw body persistence is forbidden.
- No observed tutorial POST during an optional teacher-change probe is INCONCLUSIVE residual evidence only; it does not fail N2 functional acceptance and must never be bypassed with synthetic submission.
- Runtime exceptions are reported by category only so live URLs/page/request data are not echoed to diagnostics.
- A changed post-probe tutorial locator digest or historical semantic digest is a critical zero-write failure.
- If the operator presses Enter while still unauthenticated, the harness remains in AUTHENTICATION, reports only privacy-safe session-verification facts, and either enters the historical second manual /user/login stage or fails closed; it never proceeds to tutorial evidence on an unverified session.
- A local privacy-projection contradiction (for example, an identity-bearing semantic key reaching persisted evidence) fails before file write; the privacy guard is not weakened to admit it.
- Persisted privacy-policy metadata must itself pass the same global privacy guard. False-positive schema/key collisions are repaired by renaming metadata, never by weakening the forbidden raw-data key guard.
