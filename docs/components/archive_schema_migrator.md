# Archive schema v2 migration tooling — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `archive_schema_migrator`  
**Status:** `active_d1`

## Role

- Create fresh archive-schema-v2 databases and migrate an explicitly supplied legacy archive into a separate candidate destination without changing canonical writer ownership.

## Scope

- Apply schema/archive_v2.sql to empty candidate databases.
- Migrate legacy classes/students/tutorials into normalized v2 identities, source states, memberships, collision groups and governed associations.
- Extract minimal field-presence provenance from legacy raw_json and then discard the raw blob.
- Fail closed on invalid parents, unrecognized schema shapes, missing collision identities or foreign-key violations.
- Write migration output only to a separate destination database; never migrate the canonical legacy source in place.

## Authority

- Executable schema/migration implementation for D1 candidate databases.
- No authority to modify the configured canonical local archive or transfer canonical write ownership.

- `repository_contracts`

## Writes

- `archive_v2_candidate_database`

## Must not write

- `live_gel_tutorials`
- `normalized_local_archive`

- `tutorial_post_payload`

## State transitions

- Empty destination -> fresh schema v2 candidate.
- Legacy v1 source + absent destination -> separate migrated v2 candidate.
- Any migration failure -> incomplete destination is deleted; source remains unchanged.

## Failure semantics

- Migration never guesses missing canonical parents or collision IDs.
- Legacy collision ambiguity remains blocked: candidate states are group-owned and per-ID source_state_id stays NULL.
- Foreign-key violations are hard failures.
- The D1 schema acceptance checker is offline and must not acquire requests/bs4 or other live-oracle runtime dependencies merely to validate SQLite storage behaviour.

## Dependencies

- canonical_contracts
- SQLite
- Python 3
