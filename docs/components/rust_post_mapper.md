# Rust offline POST mapper — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `rust_post_mapper`  
**Status:** `active_c2_c4_n2a`

## Role

- Purely serialize governed semantic tutorial state through origin-specific New/Revision submission types to GEL form field/value pairs without network access.

## Scope

- Validate semantic origin/type invariants before mapping.
- Use distinct NewTutorialSubmission and RevisionTutorialSubmission views so New has no datetime serialization path and Revision derives datetime only from its source TutorialIdentity.
- Serialize immutable teacher authority already bound by semantic validation; never offer a teacher reassignment writer.
- Apply successful-control checkbox semantics.
- Serialize type-applicable fields including Final Reading.
- HTML-escape editable Aims plain text before converting newlines to <br>.
- Enforce observed comment length limits.
- Remain a pure mapper whose output can be independently checked against C4 source-derived expected payloads.

## Authority

- Derived payload only; it has no permission to perform HTTP writes.
- N2a submission authority: New omits datetime entirely; Revision emits the exact source tutorial_ts; teacher attribution is immutable origin authority.

## Reads

- `semantic_form_state`
- `repository_contracts`

## Writes

- `tutorial_post_payload`

## Must not write

- `live_gel_tutorials`
- `normalized_local_archive`
- `repository_contracts`

## State transitions

- Each mapping produces an ephemeral payload from one validated semantic snapshot.
- New semantic state may transition only to a New-derived payload with no datetime key; Revision semantic state may transition only to a Revision-derived payload carrying exact source datetime.
- Any semantic edit or source-authority invalidation makes an existing payload stale.

## Failure semantics

- Invalid semantic origin/type state fails before payload construction.
- New/Revision submission constructors reject the wrong DraftOrigin.
- New datetime serialization is structurally unavailable; Revision datetime is never caller supplied or defaulted.
- Teacher mismatch against New-form or historical Revision authority fails before payload construction.
- Invalid comment lengths fail mapping.
- Source provenance is never a fallback input to submitted semantic values.
- Any C4 exact payload or mutation-isolation failure blocks phase acceptance and later networking.
