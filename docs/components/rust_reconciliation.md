# Rust reconciliation — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `rust_reconciliation`  
**Status:** `active_c3`

## Role

- Pure association logic between canonical API identities and summary states, preserving collision evidence.

## Scope

- Pair non-collision exact timestamp/date candidates without reusing consumed entries.
- Keep same-timestamp collision summary candidates group-owned rather than positionally assigning them to canonical tutorial IDs.
- Classify collision groups as identical_state, divergent_state or incomplete_evidence using governed summary state.
- Resolve revision state only when per-ID authority is proven or all collision candidate states are identical.

## Authority

- Derived association only; tutorial_id remains canonical identity and a collision candidate state cannot be upgraded to per-ID ownership without evidence.
- Shared-identical state is revision-safe because candidate states are equivalent, but the source-entry association remains ambiguous.

## Reads

- `canonical_tutorial_identity_state`
- `parsed_summary_state`
- `repository_contracts`

## Writes

- `derived_reconciliation_result`

## Must not write

- `live_gel_tutorials`
- `normalized_local_archive`
- `repository_contracts`
- `semantic_form_state`

## State transitions

- Input identity/source-state changes invalidate reconciliation result.
- Non-collision source state may become proven per-tutorial association.
- Identical collision becomes shared-identical authority without deduplicating IDs.
- Divergent or incomplete collision remains blocked for revision-by-ID.

## Failure semantics

- Divergent ambiguous collision returns no per-ID summary assignment and revision-state resolution fails closed.
- Incomplete collision evidence returns no per-ID summary assignment and revision-state resolution fails closed.
- Timestamp-only route state is never used as an implicit discriminator for canonical tutorial IDs.
