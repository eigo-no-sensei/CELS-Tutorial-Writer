# Rust edit-form validator — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `rust_edit_form_validator`  
**Status:** `active`

## Role

- Contract-driven fail-closed boundary between raw parsed GEL edit forms and semantic tutorial state.

## Scope

- Classify each applicable historical GEL control as present value, present unset, missing or malformed.
- Validate expected control kind, duplicate shape, selected-option and canonical select-option domains, complete radio option sets, positive numeric metadata and GEL date format.
- Treat browser first-option select behaviour and contract placeholders as intentional present-unset state.
- Reject known type-inapplicable tutorial controls rather than silently accepting contract drift.

## Authority

- Derived validation only; canonical expected fields/kinds/applicability/unset policy come from repository contracts.

## Reads

- `parsed_edit_form_state`
- `repository_contracts`

## Writes

- `validated_edit_form_state`

## Must not write

- `live_gel_tutorials`
- `normalized_local_archive`
- `repository_contracts`
- `semantic_form_state`
- `tutorial_post_payload`

## State transitions

- Raw parsed edit form → validated edit form only when every applicable required control is structurally valid and every forbidden known control is absent.
- Any source HTML or field-contract change invalidates previous validation output.

## Failure semantics

- Missing, malformed or disallowed-unset required controls produce a validation error report; no validated state is returned.
- Intentional placeholder/blank state is preserved as PresentUnset and is not conflated with Missing.

## Dependencies

- rust_edit_form_parser
- contract_tooling generated gel_fields
- chrono
