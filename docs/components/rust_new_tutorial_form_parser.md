# Rust New-tutorial form parser — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `rust_new_tutorial_form_parser`  
**Status:** `active_n2b`

## Role

- Validate one acquired GEL New-tutorial form into immutable source authority without weakening the historical Revision edit-form validator.

## Scope

- Parse the transient New-form HTML using the shared lexical form-control parser while keeping New semantic validation separate from Revision validation.
- Require canonical POST form action/method, matching route uid/ttype, valid customdate, hidden positive tid and complete tutorial-type-applicable governed controls.
- Require datetime to be absent on New; its presence is contract drift and never relaxes historical Revision datetime requirements.
- Construct the sole production ValidatedNewFormTeacher authority from the hidden tid and expose no public integer constructor or mutation path.
- Use canonical field identity/applicability only; never infer semantic provenance from equal values in unrelated controls.
- Produce a deterministic normalized source fingerprint without retaining raw HTML or teacher display labels.

## Authority

- Sole production writer of validated_new_tutorial_form_state and opaque New-form teacher authority.
- Validation/source interpretation authority only; GEL remains live source authority and N2b grants no tutorial submission/network-write authority.
- New and Revision form contracts remain structurally distinct; this component cannot construct validated historical edit state.

## State transitions

- Acquired New-form HTML -> ValidatedNewTutorialForm only after all canonical source controls and route/type relationships pass.
- A validation failure produces no partial validated source state.
- Authentication/session invalidation or a refetched source-form change invalidates prior New-form source authority; it must not be silently rebound.

## Failure semantics

- datetime present, hidden tid missing/wrong-kind/non-positive, route uid/type mismatch or known inapplicable governed controls fail closed.
- Missing required controls, wrong control kinds, invalid date or unknown canonical option values fail closed.
- Login/session failure is handled at acquisition and yields no parser authority; parser errors never include raw HTML in Display diagnostics.
- No failed parse returns a partially trusted teacher, date or form authority.
