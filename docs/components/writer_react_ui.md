# Tutorial Writer React presentation — active component spec

> Generated from `contracts/component_boundaries.json`. Do not edit this file directly.

**Component ID:** `writer_react_ui`  
**Status:** `active_ui1e`

## Role

- Render the selected A+D hybrid browse/write layout from safe Rust view models, collect transient credentials/input and invoke only typed UI1 Tauri commands.

## Scope

- Use CELS-derived AG Grid patterns for read-only student/tutorial navigation.
- Keep class/student/filter/busy/error/dialog/password state as presentation-only React state.
- Render only safe semantic DraftView values; never construct GEL form IDs, tid, datetime, TutorialIdentity or raw POST state.
- Send semantic TutorialDraftEdit variants only; no frontend teacher/origin/identity mutation surface.
- Clear password state in a finally block after every login attempt and use no localStorage/sessionStorage.
- Browse mode uses a focused two-pane layout: Student/Course/Attendance/Last tutorial on the left and selected-student facts/actions/history on the right.
- Write mode makes the editor dominant and keeps student context in a collapsible compact rail.
- School and internal database identifiers are not visible in the normal interface.
- React may format course ranges and tutorial labels but must not derive missing authoritative archive values.
- Render the compact CEFR level strings supplied by Rust; do not parse, strip descriptors from, or otherwise reinterpret authoritative level text in React.
- Consume DraftView.formContract rather than duplicating CEFR, assessment or InitialCourseType option domains.
- Use Rust-projected field disposition for currently rendered editable controls; hidden-preserved fields are not directly editable.
- Accept structured DraftValidationIssue objects and display their message without parsing strings for field identity.
- Do not render an Aims preset/hotlist while the assistance contract is absent_not_curated.
- Render reusable disposition-aware UI1c1 semantic controls for the existing foundation surface from Rust-projected form contracts.
- Retain and present structured DraftValidationIssue DTOs without parsing their message text for semantic authority.
- Render UI1c2 Standard, UI1c3 Initial and UI1c4 Final complete semantic form sections using only Rust-projected field dispositions, option domains and text limits.
- UI1c5 introduces no new React semantic authority; integration acceptance covers existing complete form composition.
- Render Rust Harper findings/suggestions for Aims, Teacher Comments and Final Additional Comments; apply suggestions only through typed semantic edits.
- Render the explicit local Harper dictionary panel through Tauri DTOs; never persist dictionary state in browser storage.
- Render inline Harper highlighting (mirror-div wavy underlines, spelling/grammar color variants) for Teacher Comments and Final Additional Comments; aims remains a side-panel-only assistant.
- Render per-finding actions: apply suggestion (label + full replacement text), add to dictionary (single-token gate), disable rule (session-only), skip issue (session-only).
- Hoist session-only disabled-rules and ignored-findings state to App so it survives per-field editor unmount/remount; never persist them.
- Listen for window close requests via Tauri event lifecycle, triggering DiscardDraftDialog when draft is dirty before window close.
- Display stale_source status pill and banner when draft authority is invalidated, disabling direct editing until explicit user resolution.
- Ensure all navigation paths (class selection, student change, New tutorial opening, Revision opening, logout) prompt for discard confirmation if current draft is dirty.

## Authority

- Presentation-only; backend Rust contracts are authoritative for archive, session and semantic draft state.
- Presentation-only editor-kind/composition choices do not create GEL field, applicability, option-domain, validation, draft or persistence authority.
- Type-specific React layout is presentation composition only; rust_semantic_form remains authoritative for field applicability, domains, regression semantics and candidate validation.

## State transitions

- Browse no student -> browse selected student.
- Browse selected student -> New/Revision write mode.
- Write mode -> browse selected student through discard/back; dirty state requires discard/stay confirmation.
- Login attempt -> transient password -> finally clear password.
- Structured validation issues may be displayed beside the corresponding complete type-specific field; rejected edits do not change the Rust-owned active draft.
- Active draft -> stale_source notified -> render stale banner and lock editing.
- Window close requested while dirty -> open DiscardDraftDialog; confirm -> destroy window; cancel -> stay.

## Failure semantics

- Backend errors are rendered as non-authoritative UI errors; frontend does not repair or invent semantic/source values.
- Unauthenticated state disables live New/Revision opening while archive navigation remains available.
- A field rendered by the wrong presentation branch still cannot emit an edit unless the Rust-projected disposition is editable; hidden_preserved/inapplicable fields render nothing.
- Stale source or invalid draft status disables further typed edits until draft is discarded or session is restored.
- Closing the window while draft is dirty is blocked until explicit user confirmation.
